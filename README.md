# หงส์ทอง HR — ระบบ HR, เช็คอิน และเงินเดือนพนักงาน

> **อัปเดตล่าสุด:** 2 ตุลาคม 2569 (2026)

ระบบสำหรับบริษัทสมมติ **หงส์ทอง จำกัด** — โปรเจกต์นี้เป็นงานจำลองเพื่อการศึกษา
(ไม่มีลูกค้าจริง ไม่มีงบประมาณจริง) เริ่มออกแบบจากเอกสารความต้องการแบบ SA
(`เอกสารสรุปความต้องการ - ระบบลงเวลาเข้าออกพนักงาน (ฉบับร่าง v0.1)`) เพื่อฝึกกระบวนการทำงาน
เหมือนโปรเจกต์จริง แล้วต่อยอดเพิ่มเติมเอง

**หมายเหตุสำคัญ:** เอกสาร SA ต้นฉบับระบุว่า "ไม่ลงเวลาเข้า-ออกเอง" (ให้ใช้ระบบเช็คชื่อเดิมของบริษัท
แล้วนำไฟล์มาคำนวณ) แต่เนื่องจากเป็นโปรเจกต์จำลองที่ไม่มีลูกค้าจริงมาบังคับขอบเขต จึง**ตัดสินใจ
เพิ่มระบบเช็คอิน/เช็คเอาท์ของเราเอง** เข้าไปนอกเหนือจากเอกสารต้นฉบับ และตัดส่วนนำเข้าไฟล์จาก
ระบบเดิมออก (ดู [ระบบเช็คอิน/เช็คเอาท์](#ระบบเช็คอินเช็คเอาท์))

## เทคโนโลยีที่ใช้

- **หน้าบ้าน:** Next.js 16 (App Router, `src/`, Turbopack) + TypeScript + React 19
- **ดีไซน์:** Tailwind CSS + shadcn/ui
- **หลังบ้าน:** Next.js Server Actions (TypeScript) — โค้ดที่เขียนเองมีน้อย ส่วนใหญ่พึ่ง Supabase
- **ฐานข้อมูล/Auth/Storage:** Supabase (PostgreSQL + Auth + Storage)
- **ตำแหน่งที่ตั้ง:** Geolocation API ของเบราว์เซอร์ + สูตร haversine คำนวณระยะทางในฐานข้อมูล
- **ทดสอบ:** Vitest (ยูนิตเทสต์ของ logic ล้วนๆ)
- **สคริปต์ช่วยงาน:** `tsx`
- **Deploy (แผน):** Vercel + Supabase Cloud — ต้องเป็น HTTPS เพราะ Geolocation ใช้ไม่ได้บน `http://`
  (ยกเว้น `localhost` ตอนพัฒนา)

## การตั้งค่าเริ่มต้น

### ตัวแปรสภาพแวดล้อม (`.env.local`)

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxx
SUPABASE_SERVICE_ROLE_KEY=sb_secret_xxxxxxxx
NATIONAL_ID_PEPPER=(สุ่มด้วย crypto อย่างน้อย 32 ตัวอักษร)
```

**ห้ามเปลี่ยน `NATIONAL_ID_PEPPER` หลังมีพนักงานลงทะเบียนแล้ว** เพราะใช้แฮชเลขบัตรและคำนวณรหัสผ่าน
ล็อกอิน ถ้าเปลี่ยน ทุกคนจะล็อกอินไม่ได้ทันที

### คำสั่งที่ใช้บ่อย

```powershell
npm install --legacy-peer-deps          # ติดตั้งแพ็กเกจ
npm run dev                             # รันเว็บ
npx vitest run                          # รันยูนิตเทสต์
npx supabase migration new ชื่อไฟล์      # สร้างไฟล์ migration ใหม่
npx supabase db push                    # ส่ง migration ขึ้น Supabase

# สร้าง type ใหม่ทุกครั้งหลัง db push
npx supabase gen types typescript --linked --schema public | Out-File -FilePath src/types/database.ts -Encoding utf8

# สร้างผู้ใช้คนแรก (ใช้เลขบัตรทดสอบเท่านั้น)
npx tsx scripts/create-first-user.ts --dept 20 --name "ชื่อ-นามสกุล" --national-id 1234567890121
```

**ผู้ใช้ทดสอบปัจจุบัน:** รหัสพนักงาน `69200001` / เลขบัตร `1234567890121` (แผนก 20, HR)

## ระบบล็อกอิน

ล็อกอินด้วย **รหัสพนักงาน (8 หลัก) + เลขบัตรประชาชน (13 หลัก)** ไม่มีการตั้งรหัสผ่านเอง

1. ตรวจรูปแบบและ checksum ของเลขบัตรก่อนเรียกฐานข้อมูล
2. คำนวณ "รหัสผ่านล็อกอิน" จาก `HMAC-SHA256(รหัสพนักงาน + เลขบัตร, pepper)` ส่งเข้า Supabase Auth
   ด้วยอีเมลสมมติ `<รหัสพนักงาน>@hongthong.local` (ไม่มีการส่งอีเมลจริง)
3. เลขบัตรที่เก็บในตาราง `employee_credentials` เป็นค่าแฮชคนละแบบ ใช้ตรวจเลขบัตรซ้ำเท่านั้น
   แกะกลับเป็นเลขบัตรจริงไม่ได้
4. ข้อความ error เดียวกันทุกกรณี กันคนนอกเดารหัสพนักงานที่มีอยู่จริง

**ยังไม่ได้ทำ:** จำกัดจำนวนครั้งที่ลองผิด (rate limit) มี `TODO` กำกับในโค้ดแล้ว

## ระบบเช็คอิน/เช็คเอาท์

ฟีเจอร์ที่เพิ่มเองนอกเหนือจากเอกสาร SA ต้นฉบับ

1. พนักงานเปิดหน้า `/attendance` เบราว์เซอร์ขอตำแหน่ง GPS (บังคับ) และถ่ายรูปได้ (ไม่บังคับ มีปุ่มลบ/เปลี่ยนรูป)
2. ระบบตัดสินเองว่าครั้งนี้เป็น "เช็คอิน" หรือ "เช็คเอาท์" จากประวัติล่าสุด (ผู้ใช้เลือกเองไม่ได้)
3. **เซิร์ฟเวอร์คำนวณระยะทางเองทั้งหมด** เทียบพิกัดที่ส่งมากับพิกัดบริษัทใน `app_settings`
   (ตั้งเป็นมหาวิทยาลัยกรุงเทพสุวรรณภูมิ 13.72322, 100.8024 รัศมี 200 เมตร)
4. รูปอัปโหลดเข้า Storage bucket ส่วนตัว `attendance-photos` (ไม่เปิดสาธารณะ)
5. บันทึกเวลาจากเซิร์ฟเวอร์เท่านั้น ไม่เชื่อนาฬิกาเครื่องพนักงาน

**ข้อจำกัด:** ทดสอบผ่าน `localhost:3000` บนคอมได้ แต่ทดสอบจากมือถือจริงต้อง deploy เป็น HTTPS ก่อน

**ยังไม่ได้ทำ:** หน้าแอดมินตั้งค่าพิกัด/รัศมี (ตอนนี้แก้ผ่าน SQL Editor), การเชื่อมข้อมูลเช็คอินไป
คำนวณเงินเดือน

## ระบบขอลา / อนุมัติลา

1. พนักงานทุกคนยื่นคำขอลาที่หน้า `/leave` ได้ 3 ประเภท: ลาป่วย, ลากิจ, ลาพักร้อน
2. **นับเฉพาะวันทำงาน** ไม่นับวันอาทิตย์และวันหยุดนักขัตฤกษ์ (ตาราง `holidays`)
3. ลากิจ/ลาพักร้อนต้องยื่นล่วงหน้า 1 เดือน ลาป่วยไม่ต้องล่วงหน้า แต่ยื่นย้อนหลังได้ไม่เกิน 7 วัน
4. โควตา 4 วัน/เดือน **นับตามเดือนปฏิทิน** รวมคำขอที่รออนุมัติ + อนุมัติแล้ว (ไม่นับที่ถูกปฏิเสธ)
   คำขอที่คร่อม 2 เดือนแบ่งวันเข้าแต่ละเดือนตามจริง
5. ลาเกินโควตา **ยื่นได้** แต่ระบบติดป้าย "เกินโควตา" ตอนยื่น ส่วนการหักเงินจริงคำนวณใหม่ตอนทำเงินเดือน
   จากคำขอที่อนุมัติแล้วเท่านั้น
6. ยื่นคำขอที่วันซ้อนกับคำขอที่รออนุมัติ/อนุมัติแล้วของตัวเองไม่ได้
7. ผู้อนุมัติ (หน้า `/approvals`) คือ 00/01/HR — อนุมัติคำขอของตัวเองไม่ได้ และคำขอของ 01/HR/00
   ต้องให้ผู้บริหาร (00) อนุมัติเท่านั้น (กฎกลางใน `approval_block_reason()` ใช้ร่วมกับ OT)

**วิธีเขียนข้อมูล:** ผ่าน SECURITY DEFINER function (`request_leave`, `decide_leave_request`)
ไม่ใช้ service role เพราะฟังก์ชันรู้ตัวผู้ใช้จาก `auth.uid()` เอง

**ยังไม่ได้ทำ:** ยกเลิกคำขอลาเอง, แนบใบรับรองแพทย์

## ระบบขอ OT / อนุมัติ OT

1. ขอที่หน้า `/ot` เป็นชั่วโมงเต็ม 1–4 ชั่วโมงต่อวัน (`ot.max_hours_per_day`) วันละ 1 คำขอ
2. ต้องขอ **ก่อนเวลาเลิกงาน (17:00) ของวันนั้น** เฉพาะวันทำงาน และไม่ใช่วันที่ลาอยู่
3. อนุมัติที่หน้า `/approvals` กฎผู้อนุมัติเดียวกับการลา
4. จ่ายจริง = ชั่วโมงเต็มที่ทำหลัง 17:00 (ดูจากเวลาเช็คเอาท์) แต่ไม่เกินชั่วโมงที่อนุมัติ เศษชั่วโมงตัดทิ้ง

## ระบบเงินเดือน

**รอบ:** งวด "ตุลาคม 2569" = 26 ก.ย. – 25 ต.ค. (`payroll.cutoff_day` = 25)

| รายการ | สูตร |
|---|---|
| ค่าจ้าง | (วันที่มาทำงาน + วันหยุดนักขัตฤกษ์) × 550 บาท — วันอาทิตย์/วันลา/วันขาดงานไม่ได้ค่าจ้าง |
| หักมาสาย | นาทีที่สาย × 2.5 บาท (นับตั้งแต่ 09:01) ต่อวันไม่เกินค่าจ้าง 1 วัน |
| OT | ชั่วโมงที่จ่ายจริง × 150 บาท |
| หักลาเกินโควตา | 250 บาท × จำนวน **วัน** ที่เกินโควตาของเดือนปฏิทินนั้น (วันลาเรียงตามวันที่ วันที่ 5 เป็นต้นไปคือวันที่เกิน) |
| ประกันสังคม | 5% ของ (ค่าจ้าง + OT − หักมาสาย) ปัดเป็นบาท ไม่เกิน 750 บาท |
| สุทธิ | ค่าจ้าง + OT − หักมาสาย − หักลาเกินโควตา − ประกันสังคม (ไม่ต่ำกว่า 0) |

**ขั้นตอน:** การเงิน/HR กด "คำนวณ" ได้ตลอดงวด (วันที่ยังไม่ถึงไม่นับ) → หลังพ้นวันตัดรอบกด "คำนวณใหม่"
แล้ว "ปิดงวด" → พนักงานเห็นสลิปของตัวเองที่ `/payslip` และดาวน์โหลด PDF ได้ ผู้บริหารดูได้อย่างเดียว
หัวหน้าแผนกไม่เห็นเงินเดือนลูกทีม

**คำนวณที่ไหน:** `src/lib/payroll/logic.ts` (มีเทสต์ครอบคลุมทุกกรณีในตาราง) คำนวณเป็นสตางค์ (จำนวนเต็ม)
กันปัญหาทศนิยม บันทึกทั้งงวดในทรานแซกชันเดียวผ่าน `save_payroll_run()` (service role เท่านั้น)

**คนลาออกกลางงวด:** ได้ค่าจ้างถึงวันทำงานวันสุดท้าย (`resigned_on`) วันหลังจากนั้นไม่นับเป็นขาดงาน

**ยังไม่ได้ทำ:** ภาษีหัก ณ ที่จ่าย

## ใบเตือน / ทีม / รายงาน / ตั้งค่า

- **ใบเตือน** (`/warnings`, 01/HR): กด "ตรวจและออกใบเตือนอัตโนมัติ" ของงวดที่คำนวณแล้ว
  มาสาย ≥ 3 ครั้ง หรือขาดงาน ≥ 1 วันต่องวด ได้ใบเตือน (ประเภทละครั้งต่องวด) และออกใบเตือนเองได้
  พนักงานเห็นใบเตือนที่หน้าแรกและกด "รับทราบ"
- **ทีมของฉัน** (`/team`): สถานะวันนี้ (มาแล้ว/สาย/ลา/ยังไม่มา) + การลาที่กำลังจะมาถึง
  หัวหน้าเห็นทีม 00/01/HR เห็นทั้งบริษัท
- **รายงาน** (`/reports`, 00/01/HR): Excel เงินเดือนรายงวด, การเข้างานรายวัน, คำขอลา+OT
- **จัดการพนักงาน** (`/employees`, 01/HR): ค้นหา/กรองแผนก/สถานะ, แก้ชื่อ, ย้ายแผนก (รหัสพนักงานไม่เปลี่ยน
  เพราะใช้ล็อกอิน), บันทึกลาออกพร้อมวันทำงานวันสุดท้าย (เข้าระบบไม่ได้ทันที), กลับเข้าทำงาน
  เขียนผ่าน `update_employee()` / `set_employee_status()` (บันทึกลาออกให้ตัวเองไม่ได้)
- **หน้าอนุมัติแยกตามบทบาท** (`/approvals`): การเงินเห็นคำขอเกินโควตาก่อนพร้อมยอดหักเงิน, HR กรองตามแผนก
  เรียงแผนก/ชื่อ, ผู้บริหารแยกกลุ่ม "ต้องให้คุณอนุมัติเท่านั้น" กรอบสีทอง, คำขอที่กดไม่ได้แสดงปุ่มสีจาง + เหตุผล
- **ตั้งค่า** (`/admin`, HR): แก้อัตราค่าจ้าง/OT/หัก, เวลาทำงาน, โควตาลา, ประกันสังคม, เกณฑ์ใบเตือน,
  พิกัดบริษัท และเพิ่ม/ลบวันหยุดนักขัตฤกษ์ (ไม่เปิดให้แก้การตั้งค่ารหัสพนักงาน)

## สิทธิ์การเห็นข้อมูล (RLS)

คุมที่ระดับฐานข้อมูลโดยตรง ใช้กฎเดียวกันกับตาราง `employees` และ `attendance_logs`

| ผู้ใช้ | เห็นข้อมูล |
|---|---|
| พนักงานทั่วไป | เฉพาะของตัวเอง |
| หัวหน้าแผนก | ของตัวเอง + ลูกทีมกลุ่มเดียวกัน (เช่น 30 เห็น 31) |
| 00 / 01 / HR (20-21) | ทั้งหมด |

ตารางลา, OT, ใบเตือน ใช้กฎเดียวกันนี้ ส่วนสลิปเงินเดือน: พนักงานเห็นเฉพาะของตัวเองในงวดที่ปิดแล้ว
00/01/HR เห็นทั้งหมด หัวหน้าแผนกไม่เห็น

ฝั่งเบราว์เซอร์อ่านได้อย่างเดียวทุกตาราง การเขียนข้อมูลทำฝั่งเซิร์ฟเวอร์ 2 แบบ:
**SECURITY DEFINER function** สำหรับสิ่งที่ตัดสินสิทธิ์จากผู้ใช้ได้เอง (ขอลา/OT, อนุมัติ, รับทราบใบเตือน) และ
**service role** (`src/lib/supabase/service.ts`) สำหรับลงทะเบียน, เช็คอิน, เงินเดือน, ใบเตือน, ตั้งค่า
(ตรวจสิทธิ์ด้วย `getCurrentEmployee()` ก่อนทุกครั้ง) ตาราง `app_settings` ไม่เปิดให้ฝั่งเบราว์เซอร์อ่านตรง
ค่ากติกาที่ไม่ลับเปิดผ่าน `public_settings()`

## กติกาธุรกิจจากเอกสาร SA ต้นฉบับ

- เวลาทำงาน 09:00–17:00 (พักเที่ยง 1 ชม.) ทำงาน 6 วัน/สัปดาห์ หยุดวันอาทิตย์
- ค่าจ้าง 550 บาท/วัน ทุกแผนก, มาสายนับตั้งแต่ 09:01 หักนาทีละ 2.5 บาท
- OT ชั่วโมงละ 150 บาท หลัง 17:00 เฉพาะชั่วโมงเต็ม ต้องขออนุมัติล่วงหน้า
- ลาได้ 4 วัน/เดือน (รวมทุกประเภท ยกยอดไม่ได้) ขอล่วงหน้า 1 เดือน ผู้อนุมัติคือ 00/20/21
  (คำขอของ 01/20/21 เองต้องให้ 00 อนุมัติ)
- วันลาไม่ได้รับค่าจ้าง ลาเกินโควตาหัก 250 บาท
- รอบตัดเงินเดือนวันที่ 25 (นับ 26 เดือนก่อน ถึง 25 เดือนปัจจุบัน)

ตัวเลขทั้งหมดนี้อยู่ในตาราง `app_settings` แล้ว HR แก้ได้ที่หน้า `/admin` โดยไม่ต้องแก้โค้ด
