# หงส์ทอง HR — ระบบ HR และเงินเดือนพนักงาน

ระบบสำหรับบริษัท **หงส์ทอง จำกัด** ครอบคลุมการลงทะเบียนพนักงาน คำนวณเงินเดือน การลา/OT
และรายงาน โดย**ไม่ได้ทำหน้าที่ลงเวลาเข้า-ออกเอง** (ยังใช้ระบบเช็คชื่อเดิมของบริษัท) แต่รับไฟล์
Excel/เครื่องสแกนจากระบบเดิมเข้ามาคำนวณต่อ

> อ้างอิงจากเอกสาร `เอกสารสรุปความต้องการ - ระบบลงเวลาเข้าออกพนักงาน (ฉบับร่าง v0.1)` ที่ทีม SA
> ส่งมอบ มีหลายจุดที่ยังรอ SA/ลูกค้ายืนยัน ดูหัวข้อ [ประเด็นที่รอยืนยัน](#ประเด็นที่รอยืนยันจาก-sa)

## สถานะปัจจุบัน

โปรเจกต์เพิ่งเริ่ม ยังอยู่ในเฟส MVP ทำเสร็จแล้วเฉพาะ **ฐานข้อมูล** และ **ระบบล็อกอิน**
หน้าเว็บที่เป็นฟีเจอร์จริง (ลา, OT, อนุมัติ, เงินเดือน, รายงาน) **ยังไม่ได้เริ่ม**

| ส่วน | ความคืบหน้า |
|---|---|
| ฐานข้อมูล (ตาราง, RLS, ฟังก์ชัน) | ทำแล้ว (เฉพาะแกนหลัก) |
| ระบบล็อกอิน (รหัสพนักงาน + เลขบัตร) | ทำแล้ว |
| หน้าแรกหลังล็อกอิน + โครง Layout กลาง | ทำแล้ว |
| ลงทะเบียนพนักงานผ่านหน้าเว็บ | ยังไม่ทำ (มีแค่สคริปต์สำหรับสร้างผู้ใช้ทดสอบ) |
| ขอลา / อนุมัติลา | ยังไม่ทำ |
| ขอ OT / อนุมัติ OT | ยังไม่ทำ |
| นำเข้าไฟล์เวลาเข้า-ออกจากระบบเดิม | ยังไม่ทำ |
| คำนวณเงินเดือน + สลิป | ยังไม่ทำ |
| ใบเตือน | ยังไม่ทำ |
| รายงาน (Excel/PDF) | ยังไม่ทำ |
| หน้าแอดมิน (ตั้งค่าแผนก/วันหยุด/อัตรา) | ยังไม่ทำ |

## เทคโนโลยีที่ใช้

- **หน้าบ้าน:** Next.js 16 (App Router, `src/` directory, Turbopack) + TypeScript + React 19
- **ดีไซน์:** Tailwind CSS + shadcn/ui
- **หลังบ้าน:** Next.js Server Actions (TypeScript) — โค้ดที่เขียนเองมีน้อย ส่วนใหญ่พึ่ง Supabase
- **ฐานข้อมูล/Auth/Storage:** Supabase (PostgreSQL + Supabase Auth)
- **ทดสอบ:** Vitest (ยูนิตเทสต์ของ logic ล้วนๆ เช่น การตรวจเลขบัตร, สูตรคำนวณ)
- **สคริปต์ช่วยงาน:** `tsx` (รัน TypeScript ตรงๆ โดยไม่ต้อง build)
- **Deploy (แผน):** Vercel (เว็บ) + Supabase Cloud (ฐานข้อมูล)

## การตั้งค่าเริ่มต้น

### ตัวแปรสภาพแวดล้อม (`.env.local`)

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxx
SUPABASE_SERVICE_ROLE_KEY=sb_secret_xxxxxxxx
NATIONAL_ID_PEPPER=(สุ่มด้วย crypto อย่างน้อย 32 ตัวอักษร)
```

**ห้ามเปลี่ยน `NATIONAL_ID_PEPPER` หลังมีพนักงานลงทะเบียนแล้ว** เพราะเป็นค่าที่ใช้แฮชเลขบัตร
และคำนวณรหัสผ่านล็อกอิน ถ้าเปลี่ยนจะทำให้ทุกคนล็อกอินไม่ได้ทันที และเลขบัตรที่แฮชไว้เดิม
เทียบไม่ตรงกับของใหม่

### คำสั่งที่ใช้บ่อย

```powershell
# ติดตั้งแพ็กเกจ
npm install --legacy-peer-deps

# รันเว็บ (dev)
npm run dev

# รันยูนิตเทสต์
npx vitest run

# ส่ง migration ขึ้น Supabase
npx supabase db push

# สร้างไฟล์ type จากตารางจริงใน Supabase (ทำใหม่ทุกครั้งที่แก้ schema)
npx supabase gen types typescript --linked --schema public | Out-File -FilePath src/types/database.ts -Encoding utf8

# สร้างผู้ใช้คนแรก (ทำครั้งเดียวตอนตั้งระบบ ใช้เลขบัตรทดสอบ ไม่ใช่ของจริง)
npx tsx scripts/create-first-user.ts --dept 20 --name "ชื่อ-นามสกุล" --national-id 1234567890121
```

## ระบบล็อกอิน

พนักงานล็อกอินด้วย **รหัสพนักงาน (8 หลัก) + เลขบัตรประชาชน (13 หลัก)** ไม่มีการตั้งรหัสผ่านเอง

**หลักการทำงาน**

1. ตรวจรูปแบบและ checksum ของเลขบัตรก่อนเรียกฐานข้อมูล
2. คำนวณ "รหัสผ่านล็อกอิน" จาก `HMAC-SHA256(รหัสพนักงาน + เลขบัตร, pepper)` แล้วส่งเข้า Supabase Auth
   ด้วยอีเมลสมมติ `<รหัสพนักงาน>@hongthong.local` (ไม่มีการส่งอีเมลจริง)
3. เลขบัตรที่เก็บในตาราง `employee_credentials` เป็นค่าแฮชคนละแบบ (แยกป้ายกับรหัสผ่านล็อกอิน)
   ใช้ตรวจว่าเลขบัตรซ้ำเท่านั้น แกะกลับเป็นเลขบัตรจริงไม่ได้
4. ข้อความ error เดียวกันทุกกรณี ("รหัสพนักงานหรือเลขบัตรประชาชนไม่ถูกต้อง") กันคนนอกเดารหัส
   พนักงานที่มีอยู่จริงจากข้อความ error ที่ต่างกัน

**ยังไม่ได้ทำ (ควรทำก่อนขึ้นระบบจริง):** จำกัดจำนวนครั้งที่ลองผิดต่อ IP/รหัสพนักงาน (rate limit)
กันการไล่เดาเลขบัตร มีคอมเมนต์ `TODO` กำกับไว้ในโค้ดแล้ว

## รหัสพนักงานและแผนก

รหัสพนักงาน 8 หลัก = **ปี พ.ศ. 2 หลักท้าย + รหัสแผนก 2 หลัก + เลขรัน 4 หลัก**
เช่น `69200001` = เข้าปี 2569, แผนก 20 (หัวหน้าแผนก HR), คนที่ 1 ของรอบ

เลขรันสร้างโดยฟังก์ชัน `generate_employee_code()` ในฐานข้อมูล นับแยกตามแผนกและ "รอบ" (ค่าเริ่มต้น
รีเซ็ตทุก 2 ปี อ่านจากตาราง `app_settings` แก้ได้โดยไม่ต้องแก้โค้ด — **ยังรอ SA ยืนยันวิธีนับรอบ**)

| รหัสแผนก | ชื่อ | role |
|---|---|---|
| 00 | ผู้บริหาร | executive |
| 01 | การเงิน | finance |
| 20 | หัวหน้าแผนก HR | hr |
| 21 | พนักงาน HR | hr |
| 30 | หัวหน้าแผนกช่าง | head |
| 31 | พนักงานช่าง | employee |
| 40 | หัวหน้าแผนกอาหารสด | head |
| 41 | พนักงานอาหารสด | employee |
| 50 | หัวหน้าแผนกอาหารแห้ง | head |
| 51 | พนักงานอาหารแห้ง | employee |
| 60 | หัวหน้าแผนกเครื่องใช้ในบ้าน | head |
| 61 | พนักงานแผนกเครื่องใช้ในบ้าน | employee |
| 70 | หัวหน้าเครื่องใช้ไฟฟ้า | head |
| 71 | พนักงานแผนกเครื่องใช้ไฟฟ้า | employee |

เพิ่มแผนกใหม่ได้โดยเพิ่มแถวในตาราง `departments` ไม่ต้องแก้โค้ด

## สิทธิ์การเห็นข้อมูล (RLS)

คุมที่ระดับฐานข้อมูลโดยตรง (Row Level Security) ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ

| ผู้ใช้ | เห็นข้อมูลพนักงาน |
|---|---|
| พนักงานทั่วไป | เฉพาะของตัวเอง |
| หัวหน้าแผนก | ของตัวเอง + ลูกทีมในแผนกกลุ่มเดียวกัน (เช่น 30 เห็น 31) |
| 00 ผู้บริหาร / 01 การเงิน / 20-21 HR | ทั้งหมด (สิทธิ์ของ HR ยังรอ SA ยืนยันข้อ 5 ในเอกสาร) |

การเขียนข้อมูล (ลงทะเบียน แก้ไข) ทำผ่าน **service role ฝั่งเซิร์ฟเวอร์เท่านั้น** ฝั่งเบราว์เซอร์
(`authenticated`) มีสิทธิ์อ่านอย่างเดียว

## กติกาทางธุรกิจที่ยืนยันแล้ว (จากเอกสาร SA)

- เวลาทำงาน 09:00–17:00 (พักเที่ยง 1 ชม.) ไม่มีผ่อนผัน, ทำงาน 6 วัน/สัปดาห์ หยุดวันอาทิตย์
- ค่าจ้าง 550 บาท/วัน เท่ากันทุกแผนก, มาสายนับตั้งแต่ 09:01 หักนาทีละ 2.5 บาท
- OT ชั่วโมงละ 150 บาท นับหลัง 17:00 เฉพาะชั่วโมงเต็ม ต้องขออนุมัติล่วงหน้า
- ลาได้ 4 วัน/เดือน (รวมทุกประเภท ยกยอดไม่ได้), ต้องขอล่วงหน้า 1 เดือน, ผู้อนุมัติคือ 00/20/21
  คนใดคนหนึ่ง (คำขอของ 01/20/21 เองต้องให้ 00 อนุมัติ)
- วันลาไม่ได้รับค่าจ้าง, ลาเกินโควตาหัก 250 บาท
- รอบตัดเงินเดือนวันที่ 25 (นับวันที่ 26 เดือนก่อน ถึง 25 เดือนปัจจุบัน)
- ที่มาของข้อมูลเวลา: ไฟล์ Excel/เครื่องสแกนจากระบบเช็คชื่อเดิม ไม่ใช่การลงเวลาในระบบนี้

ตัวเลขทั้งหมดนี้เก็บเป็นค่าตั้งค่าในตาราง `app_settings` (บางส่วนยังไม่ได้ย้ายเข้าตารางนี้ครบ
ในเฟสถัดไปจะทยอยย้าย) เพื่อให้แก้ตามที่ SA ยืนยันภายหลังได้โดยไม่ต้องแก้โค้ด

## ประเด็นที่รอยืนยันจาก SA

คัดลอกจากเอกสารต้นฉบับ (ข้อ 12) รวมกับที่ผมพบเพิ่มระหว่างออกแบบฐานข้อมูล:

1. ไฟล์ตัวอย่างจากระบบเช็คชื่อเดิม (คอลัมน์ รูปแบบวันที่-เวลา) ยังไม่ได้รับ
2. หักลาเกินโควตา 250 บาท: หักต่อวันที่เกิน หรือครั้งเดียวต่อเดือน / ลาป่วย-ฉุกเฉินที่ขอล่วงหน้า
   ไม่ได้ ต้องมีข้อยกเว้นหรือไม่
3. OT ชั่วโมงไม่เต็ม เศษของชั่วโมงตัดทิ้งใช่หรือไม่ / ออกก่อนครบชั่วโมงที่ขอ นับ 0 ใช่หรือไม่
4. อัตราประกันสังคม/ภาษี ที่ต้องใช้จริง และวันที่จ่ายเงินเดือน
5. สิทธิ์ HR (20, 21): เห็นข้อมูลทุกแผนกหรือไม่, ใครเพิ่มโควตาวันลาได้, ใครอนุมัติคำขอของ 00
6. ขาดงานไม่แจ้ง นอกจากใบเตือนแล้ว ไม่จ่ายค่าจ้างวันนั้นใช่หรือไม่
7. ขอบเขตงบ 1,000,000 บาท รวมโฮสติ้ง/ดูแลหลังส่งมอบ/อบรมหรือไม่ และจำนวนพนักงานทั้งหมด
8. ให้ลูกค้าตรวจสอบค่าจ้างเฉลี่ยรายชั่วโมงกับ พ.ร.บ.คุ้มครองแรงงาน (การหักค่าจ้างมีข้อจำกัด
   ตามกฎหมาย ผู้จัดทำไม่ใช่ที่ปรึกษากฎหมาย)
9. ใครเป็น "แอดมิน" ดูแลตารางแผนก/วันหยุด/อัตราต่างๆ — เอกสารพูดถึงพื้นที่แอดมินแต่ตารางสิทธิ์
   (ข้อ 3) ไม่มีระบุ role นี้ไว้
10. โควตาลา 4 วัน/เดือน นับตามเดือนปฏิทิน หรือตามรอบเงินเดือน (26–25)
11. ออกก่อนเวลา มีแต่กติกาเรื่องใบเตือน ไม่มีกติกาหักเงิน จ่ายเต็ม 550 บาทใช่หรือไม่
12. วันหยุดราชการที่ตรงวันอาทิตย์ หรือวันหยุดชดเชย จ่ายค่าจ้างหรือไม่
13. งบประมาณในเอกสารเขียนว่า "ปรับจากเดิม 50,000 บาท" เป็น 1,000,000 บาท ต่างกัน 20 เท่า
    ควรยืนยันตัวเลขที่ถูกต้องอีกครั้ง

      ถูกเปิดเผยที่ไหนมาก่อน (ชุดที่ใช้พัฒนาถูกเห็นระหว่างตั้งค่าหลายครั้ง)
