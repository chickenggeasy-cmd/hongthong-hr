# คู่มือขึ้นระบบจริง (ใช้กับพนักงานจริง)

คู่มือนี้พาเอาระบบหงส์ทองขึ้นเว็บจริงแบบ HTTPS ให้พนักงานเปิดจากมือถือได้ ทำตามทีละขั้น ไม่ต้องข้าม
ใช้เวลาประมาณ 1–2 ชั่วโมง (ครั้งแรก)

**ภาพรวม:**

1. สร้างฐานข้อมูล Supabase ชุดใหม่สำหรับใช้งานจริง (ไม่ปนกับข้อมูลทดสอบ และได้รหัสลับชุดใหม่ทั้งหมด)
2. เอาโค้ดเข้าสาขาหลัก (`main`) บน GitHub
3. เปิดเว็บบน Vercel (ฟรี) ได้ลิงก์ `https://...`
4. สร้างบัญชี HR คนแรก แล้วลงทะเบียนพนักงานจริงผ่านหน้าเว็บ
5. ทดสอบตามเช็กลิสต์ แล้วแจกลิงก์ให้พนักงาน

---

## ขั้นที่ 1: สร้าง Supabase ชุดใหม่สำหรับใช้งานจริง

**ทำไมต้องชุดใหม่:** ชุดที่ใช้ทดสอบมีข้อมูลสมมติปนอยู่ และรหัสลับ (secret key, pepper) เคยถูกเปิดเผยระหว่างพัฒนา
การเริ่มชุดใหม่สะอาดและปลอดภัยที่สุด ชุดเดิมเก็บไว้ทดสอบต่อได้

1. เข้า https://supabase.com/dashboard → กด **New project**
2. ตั้งชื่อ เช่น `hongthong-hr-prod`
3. **Database Password:** กด Generate แล้วเก็บไว้ในที่ปลอดภัย (เช่น โปรแกรมจัดการรหัสผ่าน)
4. **Region:** เลือก **Southeast Asia (Singapore)** (ใกล้ไทยที่สุด เว็บเร็ว)
5. กด **Create new project** รอประมาณ 2 นาที

### ตั้งค่าความปลอดภัยของ Supabase (สำคัญมาก)

1. เมนูซ้าย **Authentication** → **Sign In / Providers** (หรือ **Settings**)
2. **ปิด "Allow new users to sign up"** — ระบบสร้างบัญชีให้พนักงานเองตอน HR ลงทะเบียน ไม่ต้องให้ใครสมัครเอง
3. ปิด **Confirm email** (อีเมลเป็นอีเมลสมมติ `รหัส@hongthong.local` ส่งจริงไม่ได้)

### ส่งตารางทั้งหมดขึ้น Supabase ชุดใหม่

เปิด Terminal ใน VS Code ที่โฟลเดอร์โปรเจกต์ แล้วรันทีละบรรทัด:

```powershell
npx supabase link --project-ref รหัสโปรเจกต์ใหม่
npx supabase db push
```

- `รหัสโปรเจกต์ใหม่` ดูได้จาก URL ของหน้า dashboard: `https://supabase.com/dashboard/project/<รหัสนี้>`
- ถ้าถามรหัสผ่าน ให้ใส่ Database Password จากข้อ 3
- `db push` จะถามยืนยัน พิมพ์ `Y` แล้ว Enter

> หลังจากนี้ CLI ในเครื่องจะชี้ไปที่ชุดใหม่ ถ้าจะกลับไปทดสอบกับชุดเดิมให้รัน `npx supabase link --project-ref รหัสชุดเดิม`

### เก็บค่าที่ต้องใช้ (ไปใส่ใน Vercel ขั้นที่ 3)

เมนูซ้าย **Project Settings** → **API Keys** (และ **Data API**):

| ชื่อ | เอามาจาก |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL เช่น `https://abcd.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Publishable key (`sb_publishable_...`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret key (`sb_secret_...`) — **ห้ามส่งให้ใคร ห้ามใส่ในโค้ด** |
| `NATIONAL_ID_PEPPER` | สร้างใหม่ด้วยคำสั่งด้านล่าง |

สร้าง `NATIONAL_ID_PEPPER` ใหม่ (รันใน Terminal แล้วคัดลอกผลลัพธ์):

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

**ห้ามเปลี่ยน pepper หลังเริ่มใช้งานจริง** ทุกคนจะล็อกอินไม่ได้ทันที เก็บสำรองไว้ในที่ปลอดภัย

### กุญแจแจ้งเตือนบนมือถือ (VAPID) — ใส่หรือไม่ใส่ก็ได้

ใช้ส่งแจ้งเตือนให้เด้งบนมือถือ/คอม **แม้ปิดเว็บไปแล้ว** (เหมือน LINE)
ถ้าไม่ใส่: กระดิ่ง + กล่องเด้ง + เสียง บนหน้าเว็บยังทำงานปกติ แค่ไม่มีแจ้งเตือนตอนปิดเว็บ

สร้างคู่กุญแจ (รันใน Terminal ครั้งเดียว):

```powershell
npx web-push generate-vapid-keys
```

จะได้ 2 บรรทัด:

| ชื่อใน `.env.local` / Vercel | เอามาจาก | Type ใน Vercel |
|---|---|---|
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | บรรทัด **Public Key** | Config |
| `VAPID_PRIVATE_KEY` | บรรทัด **Private Key** — **ห้ามส่งให้ใคร** | Secret |

> เปลี่ยนกุญแจชุดนี้ภายหลังได้ แต่ทุกคนต้องกด "เปิดแจ้งเตือนบนเครื่องนี้" ใหม่

## ขั้นที่ 2: เอาโค้ดเข้าสาขาหลัก (`main`)

งานทั้งหมดอยู่ที่สาขา `claude/submit-work-claude-code-dz0y24` Vercel จะใช้สาขา `main` เป็นเว็บจริง

1. เปิด GitHub ของ repo `hongthong-hr`
2. จะมีแถบสีเหลือง "...had recent pushes" กด **Compare & pull request**
   (ถ้าไม่มี: แท็บ **Pull requests** → **New pull request** → base: `main` ← compare: `claude/submit-work-claude-code-dz0y24`)
3. กด **Create pull request** แล้วกด **Merge pull request** → **Confirm merge**

## ขั้นที่ 3: เปิดเว็บบน Vercel

1. เข้า https://vercel.com → **Sign Up / Log in with GitHub**
2. กด **Add New...** → **Project** → เลือก repo `hongthong-hr` → **Import**
3. **Framework Preset:** Next.js (เลือกให้อัตโนมัติ)
4. เปิดหัวข้อ **Environment Variables** ใส่ค่าจากขั้นที่ 1 (วางทั้งไฟล์ `.env.local` ในช่อง Key ได้เลย Vercel แยกให้เอง)
   - ชื่อที่ขึ้นต้นด้วย `NEXT_PUBLIC_` เลือก Type **Config** (เป็นค่าสาธารณะ ถูกฝังในหน้าเว็บอยู่แล้ว)
   - ที่เหลือ (`SUPABASE_SERVICE_ROLE_KEY`, `NATIONAL_ID_PEPPER`, `VAPID_PRIVATE_KEY`) เลือก **Secret**
   - **ห้ามใส่กุญแจ `sb_secret_...` ในชื่อที่ขึ้นต้นด้วย `NEXT_PUBLIC_`** ทุกคนจะเห็นกุญแจลับ
5. กด **Deploy** รอ 2–3 นาที
6. เสร็จแล้วจะได้ลิงก์ เช่น `https://hongthong-hr.vercel.app` — นี่คือเว็บจริง

> ไฟล์ `vercel.json` ในโปรเจกต์ตั้งให้เซิร์ฟเวอร์อยู่สิงคโปร์ (ใกล้ Supabase) แล้ว ไม่ต้องตั้งเอง

> **แก้ค่า Environment Variables ทีหลัง ต้อง deploy ใหม่ทุกครั้ง** (ค่า `NEXT_PUBLIC_` ถูกฝังตอน build)
> วิธีที่ชัวร์สุด: รัน `npx vercel --prod` ในโฟลเดอร์โปรเจกต์ (ส่งโค้ดในเครื่องขึ้นตรงๆ)
> ระวัง: ปุ่ม **Redeploy** ใน Vercel จะ build **commit เดิมของรายการนั้น** ไม่ใช่โค้ดล่าสุด

### บอก Supabase ว่าเว็บจริงอยู่ที่ไหน

Supabase → **Authentication** → **URL Configuration** → **Site URL** ใส่ลิงก์ Vercel ของคุณ แล้วกด Save

## ขั้นที่ 4: สร้าง HR คนแรก แล้วลงทะเบียนพนักงานจริง

HR คนแรกต้องสร้างด้วยสคริปต์ (หลังจากนั้นลงทะเบียนผ่านหน้าเว็บได้หมด)

1. ใน VS Code เปิดไฟล์ `.env.local` แล้ว**เปลี่ยนเป็นค่าของชุดใหม่ทั้ง 4 ค่า** (เก็บค่าชุดเดิมไว้ในไฟล์อื่นถ้ายังจะทดสอบต่อ)
2. รัน (เปลี่ยนชื่อและเลขบัตรเป็นของ HR ตัวจริง):

```powershell
npx tsx scripts/create-first-user.ts --dept 20 --name "ชื่อ นามสกุล" --national-id เลขบัตร13หลัก
```

3. จดรหัสพนักงานที่ได้ เปิดเว็บ Vercel แล้วล็อกอินด้วยรหัสนี้ + เลขบัตร
4. ไปหน้า **ตั้งค่า** ตรวจทุกค่า โดยเฉพาะ:
   - **พิกัดบริษัท (ละติจูด/ลองจิจูด):** ต้องเป็นพิกัดหน้าร้านจริง (เปิด Google Maps → คลิกขวาที่ร้าน → คัดลอกตัวเลข)
   - **รัศมีเช็คอิน:** แนะนำ 100–200 เมตร
   - **ค่าจ้าง / OT / หักสาย / ภาษีหัก ณ ที่จ่าย / ประกันสังคม** ให้ตรงกับนโยบายบริษัท
   - **วันหยุดนักขัตฤกษ์ของปี**
5. ไปหน้า **พนักงาน** ลงทะเบียนทุกคน แจ้งรหัสพนักงานให้แต่ละคน (ล็อกอินด้วยรหัส + เลขบัตรประชาชนของตัวเอง)

## ขั้นที่ 5: ทดสอบก่อนแจกจริง (เช็กลิสต์)

ใช้บัญชีจริง 2–3 คน (เช่น HR, หัวหน้า, พนักงาน) ทดสอบทุกข้อ ทั้งบนคอมและมือถือ:

- [ ] ล็อกอินได้ทุกบทบาท และเห็นเมนูถูกต้อง
- [ ] ใส่เลขบัตรผิด 5 ครั้ง ถูกล็อก 15 นาที (ปลดล็อกเร็ว: Supabase → Table Editor → `login_failures` ลบแถว)
- [ ] **เช็คอินจากมือถือที่หน้าร้านจริง** (เบราว์เซอร์ถามสิทธิ์ตำแหน่ง → อนุญาต) และถ่ายรูปได้
- [ ] เช็คอินจากบ้าน (นอกรัศมี) ต้องไม่ผ่าน
- [ ] ขอลา → ยกเลิกเองได้ตอนรออนุมัติ → ขอใหม่ → HR อนุมัติ → พนักงานเห็นผล
- [ ] ขอ OT → อนุมัติ → เช็คเอาท์หลังเวลาเลิกงาน
- [ ] HR คำนวณเงินเดือน ตรวจตัวเลข 2–3 คนด้วยมือ
- [ ] ดาวน์โหลดสลิป PDF ภาษาไทยแสดงครบ
- [ ] ดาวน์โหลดรายงาน Excel ทั้ง 3 แบบ
- [ ] หน้า **ตั้งค่า → ประวัติการแก้ไข** มีรายการที่เพิ่งทำ
- [ ] **แจ้งเตือน:** เปิด 2 เครื่อง (HR + พนักงาน) พนักงานยื่นลา → กระดิ่งของ HR เด้งทันทีพร้อมเสียง ไม่ต้องรีเฟรช
- [ ] **แจ้งเตือนตอนปิดเว็บ:** กดกระดิ่ง → "เปิดแจ้งเตือนบนเครื่องนี้" → อนุญาต → "ส่งทดสอบ" → ล็อกจอ ต้องมีแจ้งเตือนเด้ง

### ติดตั้งเป็นแอปบนมือถือ (แนะนำพนักงาน)

- **Android (Chrome):** เปิดลิงก์ → เมนู ⋮ → **เพิ่มไปยังหน้าจอหลัก / ติดตั้งแอป**
- **iPhone (Safari):** เปิดลิงก์ → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**

แจ้งเตือนตอนปิดเว็บ: Android/คอม เปิดได้จากกระดิ่งเลย · **iPhone ต้องเพิ่มไปยังหน้าจอโฮมก่อน** (iOS 16.4 ขึ้นไป) แล้วเปิดจากไอคอนนั้นจึงจะเปิดแจ้งเตือนได้

## หลังเปิดใช้งานจริง

| เรื่อง | ทำอย่างไร |
|---|---|
| สำรองข้อมูล | Supabase Free ไม่มีสำรองอัตโนมัติ และหยุดเองถ้าไม่มีคนใช้ 7 วัน → **ใช้จริงควรอัปเกรดเป็น Pro** (มีสำรองรายวัน) |
| แก้โค้ดแล้วอัปเดตเว็บ | เข้า `main` บน GitHub แล้ว Vercel อัปเดตเองภายในไม่กี่นาที |
| เพิ่มตาราง (migration ใหม่) | `npx supabase db push` กับชุด prod **ก่อน** merge โค้ดเข้า `main` |
| พนักงานลาออก | หน้าพนักงาน → จัดการ → บันทึกลาออก (ล็อกอินไม่ได้ทันที) |
| ลืมรหัสพนักงาน | HR ดูได้ที่หน้าพนักงาน (รหัสผ่านคือเลขบัตร ไม่มีการรีเซ็ต) |
| รหัสลับหลุด | Supabase → API Keys สร้าง secret key ใหม่ → ใส่ใน Vercel → Redeploy → ลบ key เก่า |

## ข้อจำกัดที่ควรรู้

- **ภาษีหัก ณ ที่จ่าย:** เป็นแบบอัตราคงที่ (%) เท่ากันทุกคน ยังไม่คำนวณขั้นบันได/ค่าลดหย่อนรายคน ถ้าต้องยื่นภาษีจริงให้ฝ่ายบัญชีตรวจสอบ
- **ประกันสังคม:** 5% เพดาน 750 บาท ตามค่าตั้งต้น ตรวจอัตราปัจจุบันก่อนใช้ (แก้ได้ที่หน้าตั้งค่า)
- **ข้อมูลส่วนบุคคล (PDPA):** ระบบเก็บชื่อ ตำแหน่งที่ตั้งตอนเช็คอิน และรูปถ่าย ควรแจ้งพนักงานก่อนเริ่มใช้ว่าเก็บอะไร เพื่ออะไร
